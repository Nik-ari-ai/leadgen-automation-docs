# ADR-002: Выбор AI-провайдера для enrichment

> **Status:** Accepted
>
> **Date:** 2026-04-20
>
> **Authors:** Arina Nikolaeva

## Контекст

Для UC-FR-04 нужен LLM-провайдер: модель должна заполнять поля лида (role, industry, summary) на основе доступных данных (email, company, website). Требования:

- Стабильное качество ответов
- Прогнозируемая стоимость
- Возможность отправки персональных данных (email) — нужен DPA для GDPR
- Поддержка JSON-ответов для парсинга

## Решение

В MVP — **OpenAI API** (модель `gpt-4o-mini` по умолчанию, с возможностью переключения на `gpt-4o` через настройки tenant). Интеграция через **адаптер** (паттерн Strategy), чтобы позже можно было добавить Anthropic / Google / локальные модели без переписывания бизнес-логики.

## Альтернативы

- **Anthropic Claude.** Плюсы: качество ответов, длинный контекст, более строгие политики безопасности. Минусы: на момент MVP — выше стоимость на простых задачах, меньше готовых интеграций для российского / европейского рынка.
- **Google Gemini.** Плюсы: интеграция с Google ecosystem, дешёвые модели. Минусы: меньше материалов / community для написания промптов под нашу задачу.
- **Локальные модели (Llama, Mistral через self-host).** Плюсы: нет передачи данных третьей стороне (легче GDPR), нет платы за токены. Минусы: высокая инфраструктурная стоимость, ниже качество без fine-tuning, не тянет MVP-команда.

## Последствия

### Положительные
- Быстрый старт: SDK зрелый, документация полная.
- DPA с OpenAI доступен.
- `gpt-4o-mini` удерживает стоимость в рамках бюджета ($10–50 на tenant в месяц).
- Адаптер позволяет менять провайдера без переписывания.

### Отрицательные
- Зависимость от внешнего сервиса: rate limits, перебои.
- Передача персональных данных в США (нужен DPA, ограничение полей).
- Стоимость растёт с объёмом — пока выручка не компенсирует.

### Нейтральные
- Промпты пишутся под особенности модели OpenAI; при смене провайдера может понадобиться доработка.
