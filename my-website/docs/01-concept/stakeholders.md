# Стейкхолдеры

## Заказчик

Реальная SaaS-компания, которая заказала продукт. Платит, утверждает. Не сидит в системе и не нажимает кнопки. Решает: нужен ли enrichment вообще, какой провайдер AI использовать, сколько денег выделить.

## Руководитель

Принимает решения по приоритетам, бюджету, стратегии. Прорабатывает решения и выносит их заказчику. Выбирает модель AI (GPT-4o vs GPT-4o-mini), устанавливает лимиты, контролирует расходы.

## Пользователи (SDR / Growth / Sales)

Основные пользователи системы.

- **SDR** — делает импорт и enrichment руками: выбирает лидов, запускает обогащение, проверяет результаты, правит вручную (human-in-the-loop).
- **Growth** — запускает кампании, консультирует, какие поля важнее для рассылок.
- **Sales** — использует обогащённые данные в работе с клиентами.

## Разработчик

Пишет код (бэкенд + фронтенд). В MVP это 1–2 человека. Реализует интеграцию с OpenAI API, систему промптов, очередь задач, логирование, кеширование, лимиты.

## Дизайнер UX/UI

Делает UI удобным (part-time, 0.2–0.3 ставки). Отвечает за то, чтобы экраны импорта, enrichment и дедупликации были понятными.

## QA

Тестирует (part-time, 0.5 ставки). Проверяет edge cases: невалидный API key, ошибка OpenAI, превышение лимита, невалидный JSON в ответе.

## Support

Помогает пользователям, собирает фидбек на пилоте. Если SDR жалуется, что «enrichment тупит» — support фиксирует и передаёт команде.

## Compliance / Legal

GDPR, политики хранения, работа с персональными данными. Решает: можно ли отправлять персональные данные лидов (email, имя, компания) в OpenAI API. Нужен ли DPA (Data Processing Agreement).

## Финансы

Контролирует расходы на OpenAI и инструменты. Утверждают бюджет (совместно с заказчиком), отслеживают фактические расходы. Если в конце месяца потратили больше — сигнализируют.
