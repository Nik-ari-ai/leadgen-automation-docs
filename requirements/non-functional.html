Нефункциональные требования

Покрыто 8 категорий из 10. Не включала всё подряд, чтобы не "раздувать" MVP.

1. Производительность​

NFR-01: Быстрая загрузка Leads​

Описание: Страница Leads должна загружать первые 50 строк + фильтры за ≤ 0.7 сек (p95) при до 50k лидов в tenant. Приоритет: Must Обоснование: иначе пользователь не ускорит подготовку базы (основная цель MVP).

NFR-02: Enrichment без зависания интерфейса​

Описание: Enrichment идёт как фоновая задача; UI не зависает. Прогресс обновляется раз в 5–10 сек. Приоритет: Must Обоснование: enrichment — ключевая фича, она должна ощущаться "живой".

2. Надёжность / Доступность​

NFR-03: Доступность MVP​

Описание: Uptime ≥ 99.5% в месяц (без плановых работ). Приоритет: Should Обоснование: простои мешают запуску кампаний.

NFR-04: Бэкап и восстановление​

Описание: Бэкап БД 1 раз в сутки, хранение 7 дней, восстановление ≤ 4 часа. Приоритет: Must Обоснование: лиды — ценность; потеря данных критична.

3. Безопасность​

NFR-05: HTTPS​

Описание: Все запросы только по HTTPS (TLS 1.2+). Приоритет: Must Обоснование: защита данных лидов в браузере.

NFR-06: Роли доступа​

Описание: Минимум 2 роли: Admin / Member. Admin управляет интеграциями и лимитами AI. Приоритет: Should Обоснование: иначе любой может сломать настройки или потратить бюджет.

4. Приватность​

NFR-07: Удаление данных (GDPR)​

Описание: Возможность удалить лид / контактные данные по запросу и логировать факт удаления. Приоритет: Must Обоснование: работа с персональными данными.

5. Масштабируемость​

NFR-08: Изоляция tenant​

Описание: Данные tenants изолированы: пользователь не может получить данные другого tenant через UI/API. Приоритет: Must Обоснование: это основа B2B multi-tenant продукта.

6. Поддерживаемость​

NFR-09: Миграции БД​

Описание: Все изменения схемы БД — через миграции (например Alembic), без ручных правок в проде. Приоритет: Should Обоснование: проще развивать продукт и меньше риск сломать рабочую версию.

7. Наблюдаемость​

NFR-10: Логи ключевых операций​

Описание: Логируются импорты (статистика/ошибки), enrichment (промпт/ответ/ошибка), экспорт (количество/фильтр) + error logs. Приоритет: Must Обоснование: иначе нельзя отлаживать качество AI и интеграций.

8. Совместимость​

NFR-11: Поддержка браузеров​

Описание: UI работает в последних версиях Chrome и Safari (desktop). Приоритет: Could Обоснование: MVP ориентирован на работу с таблицами на ноутбуке.

Что не покрыто и почему​

Accessibility​

Почему сейчас не критично: продукт — рабочий инструмент для небольшой команды, в MVP важнее скорость и основные сценарии. Риск: часть пользователей может столкнуться с неудобствами (контраст, навигация с клавиатуры). План: добавить базовые A11y-правила (контраст / фокус / клавиатура) в v1.1–v2.

Disaster Recovery / Multi-region HA (99.9%+)​

Почему сейчас не критично: высокая доступность сильно увеличивает стоимость инфраструктуры. Риск: при серьёзном падении инфраструктуры возможен простой. План: по мере роста поднять SLA до 99.9%, добавить репликацию.
