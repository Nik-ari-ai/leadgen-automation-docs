Функциональные требования (Use Cases)

UC-FR-01: Импорт лидов из CSV​

Акторы: SDR/LeadGen (пользователь), система LeadGen Automation

Предусловия:

  • Пользователь вошёл в систему
  • Выбран tenant
  • Есть доступ к разделу Leads/Import

Основной поток:

  1. Пользователь открывает экран Import
  2. Загружает CSV-файл
  3. Система показывает предпросмотр (первые N строк) и список колонок
  4. Пользователь сопоставляет колонки CSV с полями системы (email, name, company, website, title и т. д.)
  5. Пользователь нажимает Import
  6. Система проверяет данные (минимум: нужен email или LinkedIn)
  7. Система создаёт лидов и показывает итог: сколько импортировано / сколько отклонено и почему
  8. Система сохраняет отчёт импорта (дата, файл, статистика, ошибки)

Постусловия:

  • Лиды появились в таблице Leads
  • Есть отчёт импорта

Альтернативные потоки:

  • A1: В файле нет email/LinkedIn → система не запускает импорт и просит добавить
  • A2: В строках есть пустые значения → система импортирует, поля остаются пустыми
  • A3: Email неправильного формата → строка не импортируется, причина в отчёте

Потоки исключения:

  • E1: Файл не читается (битый файл/не CSV/кодировка) → импорт не запускается
  • E2: Размер файла или число строк превышает лимит → импорт не запускается
  • E3: Сбой на шаге создания (БД) → импорт останавливается, отчёт со статусом Failed/Partial
  • E4: Дубликат (email/LinkedIn уже существует) → строка не создаётся, причина "duplicate" в отчёте
  • E5: Сессия истекла во время импорта → операция прерывается

UC-FR-02: Импорт лидов из Google Sheets​

Акторы: SDR/LeadGen, система LeadGen Automation, Google Sheets API

Предусловия:

  • Пользователь вошёл в систему
  • Выбран tenant
  • Есть доступ к таблице (интеграция подключена или таблица расшарена)

Основной поток:

  1. Пользователь открывает Import → Google Sheets
  2. Вставляет ссылку на таблицу или выбирает таблицу из списка
  3. Система загружает данные и показывает предпросмотр
  4. Пользователь сопоставляет колонки с полями системы
  5. Нажимает Import
  6. Система валидирует и создаёт лидов
  7. Система показывает результат (создано/ошибки)
  8. Система сохраняет источник импорта (ссылка + дата)

Постусловия:

  • Лиды отображаются в Leads
  • Источник импорта сохранён

Альтернативные потоки:

  • A1: Нет доступа к таблице → "проверьте доступы"
  • A2: Поменялись колонки → попросить заново сопоставить поля

Потоки исключения:

  • E1: Авторизация / токен истёк → "переподключите Google", статус Failed
  • E2: Лимит API (quota / rate limit) → "лимит запросов, попробуйте позже"
  • E3: Некорректная ссылка / лист не найден → "проверьте ссылку/лист"
  • E4: Таймаут / сетевая ошибка → импорт прерывается, статус Failed/Partial

UC-FR-03: Дедупликация и merge дублей​

Акторы: SDR/LeadGen, система LeadGen Automation

Предусловия:

  • В системе уже есть лиды (после импорта)
  • Выбран tenant

Основной поток:

  1. Пользователь открывает Deduplication
  2. Система находит дубли и собирает группы (по email/LinkedIn, дополнительно — по домену + похожему имени)
  3. Пользователь открывает группу дублей
  4. Система показывает сравнение полей (что совпадает / что отличается)
  5. Пользователь выбирает главную запись (master) или подтверждает авто-выбор
  6. Пользователь нажимает Merge
  7. Система объединяет данные и помечает остальные записи как merged/archived
  8. Система показывает статистику и сохраняет историю merge

Постусловия:

  • Дубли больше не мешают в основной таблице
  • У master есть объединённые данные + история merge

Альтернативные потоки:

  • A1: Пользователь отменяет merge → ничего не меняется
  • A2: Конфликт значений (например, разные должности) → система просит выбрать вручную

Потоки исключения:

  • E1: Недостаточно прав → "нет прав", ничего не меняется
  • E2: Конкурентное изменение → блокировка, попросить обновить группу
  • E3: Сбой системы / БД во время merge → rollback, статус Failed

UC-FR-04: AI Enrichment по шаблону​

Акторы: SDR/LeadGen, система LeadGen Automation, OpenAI API

Предусловия:

  • У tenant настроен API key / модель
  • Есть лиды с пустыми полями (role/industry/summary и т. п.)

Основной поток:

  1. Пользователь выбирает лидов (чекбоксы / фильтр)
  2. Нажимает Enrich with AI
  3. Выбирает шаблон промпта
  4. Система запускает enrichment и заполняет поля
  5. Система сохраняет лог (промпт, ответ, время, статус, токены, стоимость)
  6. Пользователь открывает лида и при необходимости правит поля вручную
  7. Система сохраняет изменения и помечает "edited by human"

Постусловия:

  • Поля дополнены
  • Есть история enrichment

Альтернативные потоки:

  • A1: Лимит бюджета / квоты превышен → "лимит достигнут"
  • A2: AI ответ сомнительный → флажок "needs review"

Потоки исключения:

  • E1: Не настроен / неверный API key → "настройте интеграцию"
  • E2: Ошибка провайдера / таймаут → статус Failed в логе
  • E3: Rate limit → "лимит запросов, попробуйте позже"
  • E4: Невалидный формат ответа → "needs review", в логе ошибка

UC-FR-05: Экспорт лидов под Instantly​

Акторы: Growth/Marketing, SDR/LeadGen, система LeadGen Automation

Предусловия:

  • Есть подготовленные лиды (без дублей, с нужными полями)
  • Настроен формат экспорта (маппинг под Instantly)

Основной поток:

  1. Пользователь фильтрует лидов (статус Ready)
  2. Нажимает Export → Instantly CSV
  3. Система формирует CSV с нужными колонками в нужном порядке
  4. Пользователь скачивает CSV или копирует данные
  5. Система сохраняет факт экспорта (дата, фильтр, количество)

Постусловия:

  • CSV готов для загрузки в Instantly
  • Лог экспорта сохранён

Альтернативные потоки:

  • A1: У лида нет обязательного поля (например email) → список проблемных лидов, не экспортируются

Потоки исключения:

  • E1: Не настроен маппинг → "настройте маппинг"
  • E2: Слишком много лидов → "сузить фильтр / разбить на части"
  • E3: Сбой при генерации файла → статус Failed
  • E4: Недостаточно прав → "нет прав"
